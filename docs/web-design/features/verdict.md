# Verdict — Feature Design

## Status

A verdict panel and finalize confirmation exist in the goal workspace. In the current local adapter, verdict generation happens only after the user confirms finalization; the mock uses an 80% completion threshold. There is no demonstrated deadline scheduler, Nemotron verdict request, TTS action on the verdict panel, or share action.

## Trigger and Placement

- User opens “Finalize Goal & Run AI Verdict?” from the goal header.
- User confirms; the workspace updates goal status and renders `Verdict` when the returned goal contains one.
- Deadline passage alone does not trigger a verdict in the page flow.

## States and Content

| State         | Current behavior                                            | Design needs confirmation                               |
| ------------- | ----------------------------------------------------------- | ------------------------------------------------------- |
| Pending       | No verdict card; finalize is manually available.            | Whether and when an early verdict is allowed.           |
| Confirmation  | Modal explains the current/target values.                   | Confirm warnings and cancellation wording.              |
| Achieved      | Local score/summary/recommendation; completed at threshold. | Threshold and “exceeded” semantics.                     |
| Missed        | Local failed status and recommendation below threshold.     | Compassionate/direct voice, retry/extend action.        |
| Loading/error | No dedicated asynchronous AI state/error in mock flow.      | Define generation progress, retry, and partial failure. |

## Presentation

Current UI places verdict in the workspace after the tracker and before check-ins/history. Preserve goal title, outcome, score, summary, and next recommendation in a clear hierarchy. Whether the verdict should also appear in chat is open.

## Interaction and Motion

- Confirm finalization, then reveal the resulting verdict.
- No confetti or celebration treatment is observed.
- Share, set-another-goal, and extend-deadline actions are absent.

## Accessibility

- Announce outcome and score as a status/heading sequence; do not rely on success/failure color alone.
- Ensure modal focus management and a keyboard-operable cancel path.
- Avoid celebratory motion that ignores reduced-motion preference.

## Open Decisions

- Trigger: deadline-only, user-requested early, or both.
- Meaning of achieved/missed/exceeded and score threshold.
- Whether verdict text is generated by AI, stored, editable, or regenerated.
- TTS, share, extend deadline, and next-goal actions.
- Celebration level and transition behavior.

## API Calls

Current `api.finalizeGoal` is a delayed local simulation; no remote verdict endpoint or model response contract is verified.
